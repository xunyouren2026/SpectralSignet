## ① 定义

`F05 gen_len_eng` 定义工程指标测量时的生成步数，固定为 **48 步**。在 `_local_whitebox_detect.py` 中，系统自回归生成 48 个 token，同步测量 tok/s、KV 缓存大小、内存占用、有效带宽，并叠加几何指纹采集。

```python
gen_len_eng = 48   # 生成 48 个 token
```

（源码实测以 `--ngen 64` 运行，64 步 / 7.63s → 8.39 tok/s；48 为规格文档的工程测量标准步数。）

## ② 公式

$$tok/s = \frac{n_{gen}}{t_{gen}},\qquad BW_{eff} = W_{bytes}\times tok/s$$

帧对齐约束（与 B04 配合）：

$$n_{frames} = \frac{gen\_len\_eng}{TOK\_PER\_FRAME} = \frac{48}{8} = 6$$

## ③ 物理/几何直觉与用途

**物理直觉**：任何测量都有"热身-稳态"结构——前几个 token 包含预填充、kernel launch、缓存冷启动等一次性开销，速率偏低；步数太少时这部分主导，tok/s 估计偏低且波动大；步数足够多时一次性开销被摊薄，估计逼近真值。48 步 ≈ 5-6 秒（CPU），是"时间预算"与"统计稳定性"的交点。

几何视角：指纹采集需要曲率统计分帧（每 8 token 一帧，见 B04）。48 步恰好是 8 的 6 倍整，产出 6 帧完整数据；帧数太少则 DEFF 帧间波动（T02 非稳态告警阈值 CV>3%）无法被可靠估计。48 是"让工程指标与几何统计都能站稳"的最小整步数。

**为什么不是 16 或 128**（主文档第 4634-4638 行）：
- 16 步太短：warm-up 占比大，tok/s 波动大，带宽估算偏低
- **48 步刚好**：约 2-3 秒（GPU）/5-6 秒（CPU），足够稳定又不太久
- 128 步太长：测量更准但耗时翻倍，收益有限（48→128 tok/s 仅 8.39→8.41，+0.2%）

## ④ 推导过程

**推导 1：一次性开销摊薄模型**。设每步稳态耗时 $\tau$，一次性开销 $c$（首 token 前），则 $t(n)=n\tau+c$，$tok/s(n)=n/(n\tau+c)$。当 $n\to\infty$ 收敛到 $1/\tau$；$n$ 越小，$c$ 的拖累越大：

$$tok/s(16) < tok/s(48) \le tok/s(128) \to 1/\tau$$

用实测标定（Qwen0.5B CPU）：$t(64)=7.63\text{s}\Rightarrow\tau\approx0.1192\text{s}$。令 $c=0.068\text{s}$，则：

$$t(16)=1.975\text{s}\Rightarrow tok/s=8.10;\quad t(48)=5.79\text{s}\Rightarrow8.29;\quad t(128)=15.33\text{s}\Rightarrow8.35$$

与主文档 8.10/8.39/8.41 趋势一致（48→128 收敛、增益递减）。

**推导 2：稳定性与步数**。设每步时间 i.i.d.，方差 $\sigma^2$，则 $n$ 步总时间方差 $n\sigma^2$，$tok/s$ 的相对波动 $\propto 1/\sqrt{n}$。48 步相对 16 步波动降为 $1/\sqrt{3}\approx58\%$——这就是"48 步稳定、16 步波动大"的定量来源。

**推导 3：帧对齐**。$48=6\times8$，确保曲率统计 6 帧完整对齐；若用 50 步则会留 2 个 token 的残帧，破坏 B08 NFRAME 的整帧统计。

**实测状态**：F05 = 理论（[审计报告](file:///c:/Users/小冰/Desktop/宇宙/AIQ/AI几何指纹插件_参数审计与实验报告.txt)第 74 行：48 为设计步数；实际运行用 --ngen 64，机制已验证）。

**合成数值验证（[verify.py](verify.py)）**：
- 合成计时模型（τ=0.1192s/步 + 一次性开销 c=0.068s + 1% 噪声，固定种子）：16/48/128 步 tok/s ≈ 8.10/8.29/8.35，趋势与主文档一致（16<48≤128，收敛）✅
- 48 步 tok/s 落在 8.39±6% 内 ✅
- 帧对齐：48 = 6×8（B04 整倍数）✅
- 稳定性：多次重复的 CV（变异系数）48 步 < 16 步（波动随 $\sqrt{n}$ 下降）✅
- 有效带宽 = 1.98e9×tok/s ≈ 16.6GB/s（±8% 内）✅

## ⑥ 与关联参数的关系

| 参数 | 关系 |
|---|---|
| A03 gen_len | 曲率分析用 96/256（A 组），工程测量用 48（F 组），独立配置；48 是工程指标专属 |
| B04 TOK_PER_FRAME | 48 = 6×8，保证曲率分帧整对齐（6 帧完整） |
| F02 bandwidths | 48 步实测 tok/s 是 F02 带宽预测的实测对照输入 |
| B08 NFRAME | 帧数由 gen_len_eng/TOK_PER_FRAME 决定，影响曲率统计稳定性 |
| 501 tok/s | 输出指标：由 gen_len_eng 步数计时直接得到（实测 8.39） |
| 505 内存带宽 | 输出指标：W_bytes×tok/s，48 步测得的 tok/s 是带宽反推的输入 |
| T02 非稳态告警 | 帧间 CV>3% 告警：帧数（取决于 gen_len_eng）不足时 CV 不可靠 |
