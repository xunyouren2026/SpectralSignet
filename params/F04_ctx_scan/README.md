## ① 定义

`F04 ctx_scan` 定义 KV 显存公式计算的扫描档位，共 4 档：

```python
ctx_scan = [1024, 4096, 16384, 65536]   # token 数
```

覆盖从短上下文（1K）到超长上下文（64K）的典型范围，用于计算各档位下的 KV 缓存大小、绘制"KV vs 上下文长度"曲线，并定位 **KV 主导点**（KV 首次反超模型权重的上下文长度）。

**档位选取理由**（对数间隔，4 倍递增）：1024=RAG 常见短上下文基准；4096=标准长上下文（多数模型训练长度）；16384=长文档/长视频；65536=超长上下文极限测试。4 倍递增保证曲线采样密度在对数尺度上均匀，足以外推单调线性趋势。

## ② 公式

$$KV(ctx_i) = kv_{per\_tok} \times ctx_i,\qquad i\in\{1,2,3,4\}$$

$$KV\text{主导点} = \frac{W_{bytes}}{kv_{per\_tok}} \quad (\text{即 } KV/W = 100\% \text{ 的解})$$

```python
kv_per_tok = 168 * 1024        # 主文档示例口径: 168KB/tok
ctx_scan = [1024, 4096, 16384, 65536]
ratio = kv_per_tok * ctx / weight_bytes * 100
```

**口径标注**：主文档 F04 全部示例使用 168KB/tok（n_kv=8/h_d=112 或十进制取整 168,000B/tok）。实测口径为 24.6KB/tok（2KV/64hd，见 [wb_full.log](file:///c:/Users/小冰/Desktop/宇宙/AIQ/wb_full.log)）。两份口径的曲线形状相同（同斜率线性），但量级相差 7 倍，KV 主导点相差约 6.8 倍。verify.py 同时验证两套口径并明确标注。

## ③ 物理/几何直觉与用途

**物理直觉**：KV 是"随上下文线性累积的显存税"。扫描 1K→64K，KV 从微不足道一路涨到超过权重。**KV 主导点**是部署的分水岭：在此之前权重主导显存（模型"存得下"就"跑得动"），在此之后 KV 主导（显存需求由上下文长度而非模型规模决定）。对主文档口径，Qwen0.5B 在 ~12K 处反超；对实测口径则在 ~79K 处——说明该 0.5B 模型在常规上下文（≤32K）内仍属"权重主导"型，KV 压缩（谱记忆）在超长上下文才真正划算。

几何视角：KV 曲线的斜率正是 kv_per_tok——即"流形上每个新增采样点的存储代价"。斜率越缓（kv_per_tok 越小），流形越"可压缩"（与 106 压缩比 head_dim/k90 呼应），模型越耐长上下文，且与模型规模无关。

**用途**：① 回答"KV 何时反超权重"；② 长上下文显存瓶颈定位（看 64K 档）；③ 为推理框架提供 KV 预留预算曲线。

## ④ 推导过程

**推导 1：KV 主导点**。$KV/W = kv_{per\_tok}\cdot ctx / W_{bytes}$。令其 = 1：

$$ctx^* = \frac{W_{bytes}}{kv_{per\_tok}} = \frac{1.98\text{e}9}{168{,}000} \approx 11{,}786 \approx 12\text{K tokens}$$

（主文档口径；实测口径为 1.98e9/24,576 ≈ 78.7K。）

**推导 2：各档位 KV 与占比**（主文档口径，168,000B/tok，W=1.98e9）：

$$KV(1024)=168{,}000\times1024=172.0\text{MB}\ (8.7\%),\quad
KV(4096)=688.1\text{MB}\ (34.8\%)$$

$$KV(16384)=2.75\text{GB}\ (139.0\%\leftarrow\text{主导}),\quad
KV(65536)=11.0\text{GB}\ (556.0\%)$$

档位 4 倍递增 ⟹ KV 也 4 倍递增：$KV(4096)=4\times KV(1024)$，即 $688.1/172.0=4.00$（精确线性标度）。

**推导 3：主导点与模型规模解耦**。$ctx^*=W_{bytes}/kv_{per\_tok}$ 中，W 与 kv_per_tok 都随模型规模近似同比例增长（层数×头数×维度 ≈ 参数量），故主导点对模型规模不敏感，只由架构"形状"（头数配置、dtype）决定——这正是主文档表格 Qwen0.5B 与 Qwen7B 主导点均为 ~12K-28K 的原因。

## ⑥ 与关联参数的关系

| 参数 | 关系 |
|---|---|
| F03 kv_ctx | F04 的每个档位就是一次 F03 预测：KV=kv_per_tok×ctx；F03 提供常数，F04 提供档位列表 |
| F01 ctx | F01 是实际前向测试的单一 ctx（默认 4096 降档 1024），F04 是纯公式扫描档（可到 64K，不受实际 OOM 限制） |
| G05 max_ctx | 黑盒 API 计时上限 4096；F04 白盒显存公式可超 4096，约束来源不同 |
| 502 KV_bytes | 输出指标：F04 曲线上的每一点即 502 在不同 ctx 下的预测值 |
| 504 RSS/VRAM | 显存规划对象：F04 曲线 + 权重 + 激活 = 部署显存预算 |
| 106 ratio / 506 压缩率 | kv_per_tok 越小，KV 曲线越缓，KV 主导点越远，谱记忆压缩（head_dim/k90）收益越大 |
