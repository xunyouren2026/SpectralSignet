# G05 max_ctx：黑盒计时最大上下文

> 数据源：《几何指纹：AI模型的家族级溯源与抗微调鲁棒性参数附录表完整版.md》第 5520-5632 行

## ① 定义

`G05 max_ctx` 定义黑盒模式下计时循环的最大上下文长度，固定为 **4096**。在远程 API 黑盒测试中，系统无法直接获取模型内部激活，只能通过 API 调用测量推理速度；`max_ctx` 控制计时扫描的上限——当扫描不同上下文长度时，最大不超过 4096 token，超过则跳过（防超时、防分段计费）。

```python
ctx_values = [512, 1024, 2048, 4096]  # ≤ max_ctx
for ctx in ctx_values:
    elapsed = measure_api_time(prompt[:ctx])
```

## ② 公式

设候选上下文集合 $\mathcal{C}=\{512,1024,2048,4096,8192,\dots\}$，黑盒计时只执行满足约束的项：

$$\text{run}(ctx) = \begin{cases} \text{True}, & ctx \le \text{max\_ctx} \\ \text{False}, & ctx > \text{max\_ctx} \end{cases}$$

计时模型（decode 阶段近似线性于上下文）：

$$t(ctx) \approx a + b\cdot ctx$$

其中 $a$ 为固定开销（API 往返/预填充），$b$ 为每 token 增量耗时。

## ③ 物理/直觉与用途

**物理直觉**：白盒模式可直接读取内部激活算指纹；黑盒模式只剩"测速"这一可观测通道。上下文越长，推理耗时与计费成本越高。`max_ctx` 是一道**成本/风险护栏**：既保证扫描覆盖足够多档位以刻画 tok/s 曲线，又防止超过 API 上下文上限（DeepSeek V4 默认 4096）导致超时或意外分段计费。

**用途**（测试范围与安全性控制）：

| 上下文长度 | 测试成本 | 风险 | 用途 |
|---|---|---|---|
| 512 | 低 | 无 | 快速验证 |
| 1024 | 低 | 无 | 标准短上下文 |
| 2048 | 中 | 无 | 中等长度 |
| **4096** | **中** | **无** | **上限（max_ctx）** |
| 8192+ | 高 | 可能超时/分段计费 | 超出黑盒测试范围 |

## ④ 推导过程

**推导 1：为何 4096 是"最大安全测试长度"**。DeepSeek V4 等 API 默认上下文窗口上限为 4096，超过后要么请求被拒、要么触发分段计费。因此 4096 = "常用 API 上限"与"黑盒测试安全上界"的重合点。

**推导 2：扫描档位的几何覆盖**。档位 $\{512,1024,2048,4096\}$ 呈 2 倍递增，覆盖 $[512,4096]$ 整个数量级区间，足以外推 $t(ctx)=a+b\cdot ctx$ 的线性关系（4 点线性拟合，2 自由度冗余校验）。

**推导 3：与 F01/F04 的区分**。三者都用 4096 附近的上下文量级，但作用对象不同：F01 ctx 用于白盒 KV 缓存测试（内存受限，OOM 自动降档到 1024）；F04 ctx_scan 用于显存公式计算（可到 65536）；G05 max_ctx 用于黑盒 API 计时（成本/超时受限）。三者共享"上下文长度"物理量但约束来源不同。
